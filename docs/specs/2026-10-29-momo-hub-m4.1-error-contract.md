# M4.1 错误契约统一 — 设计规格与实施计划（合并稿）

- **状态**：已定稿（M4 探查 C2 事实）
- **上游**：m4-roadmap §1 C2（已批准）
- **定位**：RpcRemoteError.code 到 renderer 的统一传递。**studio 侧全量，协议零改，hub 仓零改动。**

## 1. 事实基线（探查定案）

- 仅 `hub:taskAnswer` 有 `[code] message` 前缀编码（`electron/src/main/hub/ipc.handlers.ts:115-119`，Electron #24427 只保 message）。
- 裸抛 RpcRemoteError 的通道全集：group.*×6（:57-62）/ mirrorWorkspace（:66-75）/ taskList/taskDelegate/taskCancel（:89-110）/ view.*×8（:125-145）/ submitRoutedTask/routingPrecheck/retryDispatch（:188-209）+ dispatchSubmitPorts/redispatchPorts 内 delegate 调用（:163/:202）。
- 消费端：`DelegatedTaskCard.tsx:418-436` regex `/^\[([a-z_]+)\] ([\s\S]*)$/` + `ANSWER_VERSION_LOW_CODES`；`hub-view.store.ts:145-150` humanizeViewError 按「已关闭本组查看/不在线/离线」**message 子串**匹配（对 hub 措辞脆弱）；MirrorWizard 走事件载荷 code（wire 级，非 IPC rejection，不在本票面）。
- RpcRemoteError 定义：`client.ts:19-26`（readonly code）。

## 2. 设计

### 2.1 electron 主进程：统一包裹

- `ipc.handlers.ts` 新增内部 helper `coded<T>(fn: () => Promise<T>): Promise<T>`——catch `RpcRemoteError` → rethrow `Error(`[${code}] ${message}`)`（与 taskAnswer 现格式逐字一致）；taskAnswer 现场内联包裹改用 helper（行为零变化）。
- **全部 hub 通道迁移**到 coded 包裹（清单=§1 全集，含 ports 内 delegate 调用点）。
- 非 RpcRemoteError 错误原样透传（不动 user-facing-error/redact 链）。

### 2.2 renderer：共享解析 + humanize 改 code 驱动

- 新建 `renderer/src/lib/rpc-error.ts`：`parseRpcErrorCode(e: unknown): {code: string; message: string} | null`（前缀 regex 单源，从 DelegatedTaskCard 上提）；DelegatedTaskCard 改消费（ANSWER_VERSION_LOW_CODES 判定不变）。
- `humanizeViewError`（hub-view.store.ts）改 **code 优先**：先枚举 hub view 面实际错误码（探查/实施时从 hub 仓 remote-view.ts errPayload 调用点核对——forbidden/not_online/view_consent_required 等，以 hub 实码为准）映射现有人话文案；无 code 或未知 code → 回落现子串匹配（**双保险，不删旧路径**——旧 hub 1.x 无前缀场景仍可达）。人话文案零变化（锁既有 UI 文案测试）。
- 全仓 sweep：grep `\[([a-z_]+)\]` 与 message 子串消费点（view/委托/组/mirror 面），逐一确认迁移或保留理由。

### 2.3 契约测试（双侧）

- electron 侧：coded 包裹单测（RpcRemoteError→前缀；普通 Error 原样）+ 每类通道一例集成断言（沿 M3.1 `[code]` 契约测试模式）。
- renderer 侧：parseRpcErrorCode 单测 + humanizeViewError code 驱动/子串回落双路径用例 + **双侧同 fixture 等值锁**（error-prefix 双侧模式）。
- 既有文案锁全绿（e2e 场景 7/8 的 toast 断言、hub-distribution/hub-view 单测）。

## 3. 票据

- **V1 studio 全量**（分支 m4.1）：coded helper + 全通道迁移 + rpc-error.ts + humanize 双路径 + sweep + 双侧契约测试；全量 electron+renderer 绿 + typecheck + lint。
- **V2 收尾**：alpha.42 + CHANGELOG + PR + CI 绿 + oracle + 合并冻结。

## 4. 风险

| 风险 | 缓解 |
|---|---|
| 前缀污染既有 message 子串消费 | humanize 双保险回落；sweep 逐点确认；e2e/单测文案锁全绿为门 |
| 通道漏迁 | 通道清单测试锁（枚举 ipc.handlers 注册面断言全部走 coded）或 sweep grep 验收 |
| 视图错误码与 hub 实码漂移 | 实施时以 hub 仓 errPayload 实码核对建映射表；未知码回落子串（永远可达） |

## Review Focus（呈 Momus）

1. 双保险回落（不删子串路径）与「统一」目标的边界是否自洽（答案：统一=主路径 code 驱动，子串降为兼容层）。
2. coded helper 对 ports 内 delegate 调用（非 ipcMain.handle 面）的包裹语义（那里错误走向是 dispatch 链非 renderer 直抛——是否应包、包在哪一层）。
3. 通道清单锁的机制选择（注册面断言 vs grep 验收）。
4. humanize 映射表与 hub 实码的核对义务落点。
