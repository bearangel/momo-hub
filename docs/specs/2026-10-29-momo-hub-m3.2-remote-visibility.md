## 2. 设计

### 2.1 协议（hub 仓，版本 0.1.8，PROTOCOL_VERSION → '1.4.0'）

1. `VIEW_RPC` + `workspaces: 'view.workspaces'`、`files: 'view.files'`；`METHOD_REQUIRED_MINOR` 显式 `[RPC.view.workspaces]=4`、`[RPC.view.files]=4`（task.answer 模式）。
2. 新类型：`ViewWorkspacesReq {targetNodeId, groupId?}` / `ViewWorkspaceSummary {id, name, description}` / `ViewWorkspacesRes {workspaces: ViewWorkspaceSummary[]}`；`ViewFilesReq {targetNodeId, workspaceName, op: 'list'|'read', path?, groupId?}` / `ViewFilesRes`（list → `{entries: {name, isDirectory, size}[], truncated}`；read → `{content: string(base64), size, truncated}`）。
3. **既有 6 方法 req 全部增可选 `groupId?`**（向后兼容：缺省走 commonGroupId 旧路径，1.2/1.3 调用者零变化）。
4. 限额（hub 侧常量，对齐既有表）：path ≤512；entries ≤500/目录（truncated 标记）；read ≤256KB（`TAIL_CONTENT_MAX` 同值）+ base64。

### 2.2 hub 实现

- `groups.ts`：view.* 提取器改造——`reqStr(p,'groupId')` 存在则用之（group.transfer :113 模式），否则回落 `viewTargetGroup`；`checkGroupRole` 零改（leader 校验通用）。
- `remote-view.ts handleView`：`groupId` 存在时同组校验从 `commonGroupId(...)` 换成 `isMember(db, groupId, targetNodeId)`（:50-52）+ 该组存在性由 checkGroupRole 先行；缺省保持 commonGroupId。**新方法无新逻辑**——走既有 forward/consent/超时通用路径。
- `server.ts`：RPC_HANDLERS 注册两条（`viewHandler` 闭包 :105 模式）。

### 2.3 studio worker（electron）

- `view-server.ts` switch 增两分支（default 前）：
  - `workspaces`：`listWorkspaces()` 投影 `{id,name,description}`——**不暴露 directoryPath/ownerId**（本机路径泄漏面，注释说明）。
  - `files`：`findWorkspaceIdByName` → 行 `directoryPath` → `new WorkspaceFS(directoryPath)`（**无 extraRoots，只读=工作空间根域**）→ op list：`assertInWorkspace(path ?? '.')` + `listDir` 截 500 + truncated；op read：`readFile` 截 256KB + truncated + base64（`CONTENT_MAX` 模式）；path 校验失败 → not_found（沿 anti-probe :167-171 口径）。**零写调用**（只读红线）。
- 限额常量：`FILES_ENTRIES_MAX=500`、`FILES_READ_MAX=256*1024`（:40-47 区）。
- `hub/index.ts` 零改（Object.values 自动路由）。

### 2.4 studio leader（renderer + main）

- main IPC：`hub:viewWorkspaces` / `hub:viewFiles`（`ipc.handlers.ts:119-132` 三行模式 + preload + types.d.ts）。
- picker 数据源切换：`WorkgroupView.handleOpenView` → `hubSupportsMinor(hubProtoVer, 4)` 时 `viewWorkspaces`（带 `groupId`=当前选中组）远端清单；否则回落本机清单（旧 hub 兼容，注释注明）。`ViewPickerDialog` UI 零改。
- `RemoteViewPane` 增「文件」tab：复用既有 tab 容器形态；懒加载目录树（进 tab list 根目录，逐层展开）；文件点击 read 预览（文本域，base64 解码）；错误沿 `humanizeViewError` 既有链。**无新布局语言**（P2 口径：新 tab 复用既有 TABS 容器与列表样式，数据源切换零 UI 变化；验收截图留证）。
- store：`hub-view.store.ts` 增 files 子域（目录栈 + 内容缓存 + 分页 truncated 标记），teardown 不需 unsubscribe（files 无订阅）。
- 调用一律带 `groupId`（选中组上下文——boundary 铁律 5：路由目标用当前上下文）。

## 4. 风险

| 风险 | 缓解 |
|---|---|
| listDir 无分页大目录慢/超大 | 500 截断 + truncated 标记；remote 端 size 统计已有（DirEntry） |
| base64 传输体积膨胀 | 256KB 上限对齐 TAIL_CONTENT_MAX；truncated 明示 |
| 只读红线被新分支破坏 | 静态断言测试自动覆盖（写 SQL 即红） |
| groupId 向后兼容破坏旧调用 | 可选字段 + 缺省 commonGroupId 回落 + 旧形状零变化锁 |
| 本机路径泄漏 | workspaces 投影白名单三字段；files 全程 relpath + assertInWorkspace |
