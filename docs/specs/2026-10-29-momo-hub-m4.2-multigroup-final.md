# M4.2 多组终态 — 设计规格与实施计划（合并稿）

- **状态**：已定稿（M4 探查 C1 事实）
- **上游**：m4-roadmap §1 C1（已批准）
- **定位**：commonGroupId 消退的**终态收口**。协议 minor **1.6.0**（与 M4.3 同车，本期先占号）。两仓改动。

## 1. 事实基线（探查定案）

- commonGroupId 残余四点：def（hub groups.ts:94-106）/ viewTargetGroup 回落（:111，8 个 view.* 缺省路径）/ handleView 回落（remote-view.ts:158）/ **handleTail 订阅复检（remote-view.ts:216）——订阅记录 (leader,target,sessionId) 不存 groupId，显式订阅后复检也退化为 commonGroupId**。
- TaskRecord 无 groupId（协议 delegation.ts:45-59）——studio 委派板 taskList() 无过滤跨组聚合（hub-delegation.store.ts:120），卡无法按组归属。
- presence 全局（hello onlineNodes + node.online/offline 全广播）；resource HTTP 面全局。
- studio 侧 M3.2 起 view 调用已全显式带 groupId（groupSeg()）；WorkgroupView 无选中组时 groupId=null → hub 回落。

## 2. 设计

### 2.1 协议 1.6.0（hub 仓，版本 0.2.0）

1. `ViewSubscribeReq`/订阅链路增可选 `groupId?`；`view.tail` 推送载荷增可选 `groupId?`（订阅时透传记录）。
2. `TaskRecord` 增可选 `groupId?: string`（task.list/delegate 回执带出——**从 delegations 表既有 group_id 列直接投影，零迁移**）。
3. PROTOCOL_VERSION → '1.6.0'（注释：view 订阅组锚定 + TaskRecord 组归属，向后兼容可选字段）。
4. 裁定记录：**presence 保持全局**（节点发现是跨组需求，非缺陷——关闭该项）；resource 面组化不在本期（与 M4.4 治理同裁定域）。

### 2.2 hub 实现

- **订阅记录扩 groupId**（内存 Map 结构 + view.subscribe 处理器存 payload.groupId ?? commonGroupId 推导值）；handleTail 复检改用**记录值**（有显式值走 isMember 该组；无记录值回落 commonGroupId——旧订阅者零变化）。
- handleDelegate/task.list 输出 TaskRecord 带 group_id 投影。
- 测试：订阅带 groupId 多组消歧（commonGroupId 本可命中但他组的场景——tail 推送正确组锚定）；旧订阅形状零变化锁；TaskRecord 键集扩 groupId（delegations.test.ts:529 同步）；minor 门槛三态（1.5 peer 调新字段方法不受影响——纯可选字段无新方法，**METHOD_REQUIRED_MINOR 零登记**）。

### 2.3 studio 实现

- pin `#v0.2.0` + protocol-pin 测试。
- 委派板组归属：`DelegatedTaskCard` 显示组徽标（TaskRecord.groupId 有值时，组名经 group.list 映射缓存）；`hub-delegation.store` taskList 调用带**选中组 groupId 过滤**（WorkgroupView 上下文——铁律 5；无选中组=全组聚合保持现状）。
- view 订阅链（hub-view.store openPanel/subscribe）携带 groupId（已有 groupSeg——验证 subscribe 路径也带，缺则补）。
- 测试：组徽标渲染门控（有/无 groupId）、taskList 过滤透传、订阅载荷 groupId。

## 3. 票据

- **W1 hub**（分支 m4.2）：协议 1.6.0 + 订阅组锚定 + TaskRecord 投影 + 测试 → **0.2.0 bump + tag `v0.2.0`**（minor 版本跨 0.1.x→0.2.0 与协议 1.6.0 对齐）。
