## 1. 目标与非目标

**目标**

1. 协议兼容前置：让后续 M3.1/M3.2 的新 RPC 对旧节点**显式降级**（可读错误 + 版本可见），而非静默 `unknown_method`。
2. 清偿 M2 系列遗留的 5 项已定案债务（0-2/0-3/0-4/0-5/0-7）。

**非目标（明确不做）**

- 0-6 readonly 持久化（维持 M2.5「设计边界」裁决，已批准不纳入）。
- 协议版本号提升到 1.3.0（留给 M3.1 实际新增方法时一并提）。
- hub 默认端口变更（8787 不动；`*:18787` 是验收期绑定，非产品行为）。
- 任何 M3.1+ 的功能实现。

## 3. 票据设计

### 3.1 T1 · 协议能力协商 / 最低 minor 门槛

**设计原则**（momo-boundary-rules）：新增字段/方法，不改既有字段语义；两端同 commit；契约测试锁形状。

**语义分层**：`PROTOCOL_VERSION = major.minor.patch`
- major 不匹配 = 不兼容（现状保留，拒绝连接）。
- **minor = 向后兼容的新增**（新方法、新可选字段）。接收端遇未知可选字段忽略（现状已如此）。
- 由此「能力门槛」= per-feature 的 `requiredMinor`，不做全局 caps 数组（caps 需要维护全集，易漂移；minor 分层复用版本号天然有序）。

**新增四件**：

1. **版本全量可见**：hub 在握手/注册响应中携带完整 `protocolVersion`；node 注册载荷携带 node 侧完整版本，hub 持久化到节点记录。※ 精确挂载点待探查回填。
2. **分发层结构化降级**：RPC 分发遇「方法存在但需更高 minor」时返回结构化错误 `unsupported_method`，载荷含 `{method, requiredMinor, hubVersion}`；对真正不存在的方法保留 `unknown_method`。hub 侧维护 `method → requiredMinor` 表（M3.0 建表，仅含既有方法=1.2 基线；M3.1/M3.2 增量登记）。
3. **双仓辅助函数** `protocolSupports(peerVersion, requiredMinor)`：major 相等且 peer minor ≥ requiredMinor。双仓各一份实现 + 双侧契约测试对齐语义。
4. **studio 消费管道**：主进程保存 hub 版本（连接时获取），诊断/设置界面显示 hub 协议版本；M3.1/M3.2 的功能门控消费此值（本票只铺管道不加门控）。

**兼容矩阵（验收口径）**：

| 场景 | 期望 |
|---|---|
| 1.2 node ↔ 1.2 hub | 全现状行为，零变化 |
| 旧 studio（1.2）→ 新 hub（1.3+）调 1.3 方法 | `unsupported_method` + `{method, requiredMinor, hubVersion}`，可读降级 |
| 新 studio → 旧 hub 调 1.3 方法 | 同上（hub 分发层同错误）；studio UI 层再吃 requiredMinor 给版本提示（M3.1 消费） |
| major 不匹配 | 现状拒绝行为不变 |

### 3.2 T2 · 非 2xx 下载人话化

- 映射表（`hub-install.ts` 下载错误抛出点接入）：
  - `404` → 资源包不存在或已下架
  - `403` → 无权访问该资源包
  - `5xx` → hub 服务异常，请稍后重试
  - 其余非 2xx → 下载失败，请稍后重试
- 纪律：人话文案进卡片（经 `error-prefix.ts` 单前缀集合）；`HTTP <status> <url脱敏>` 原文进日志（`includeQueryToken` 沿用 M2.5 redact 规则）。
- 契约测试：映射表逐条 + 兜底条 + 「日志有原文、UI 无原文」双向断言。

### 3.3 T3 · hookTimeout 固化

- `renderer/vitest.config.ts` 增 `hookTimeout: 60000`。验收 = 不带任何 CLI 参数全量跑绿。

### 3.4 T4 · hub MOMO_HUB_HOST 硬化

- 新增 `MOMO_HUB_HOST` 环境变量（默认 `127.0.0.1`）；显式配 `0.0.0.0` 时启动日志 WARN（跨主机接入提示）。端口行为不变。
- 测试：默认值 / 显式 host / 非法值（回退默认 + WARN）三态。
- 文档：README/运行手册补一句。

### 3.5 T5 · keychain 服务名作用域化

※ 设计定稿待探查回填（profile 标识符来源）。草案：
- profile id = user-data-dir 绝对路径 sha256 前 8 hex。
- **默认 profile（无 AP_USER_DATA_DIR）服务名不变**（既有用户 key 兼容）；非默认 profile → `<base-service>-<hash8>`。
- 写/读/删三面同用作用域函数；探查确认后补迁移/清理口径。

### 3.6 T6 · CI e2e 解禁

※ 方案待诊断回填。约束：不接受 skip-if-CI 类守卫，须真实适配（交互 API 换代 / 焦点策略 / 视口调整）；解禁 = 删 testIgnore 后 CI 三连绿。

## 4. 测试与验收面

- **单测**：双仓全绿（electron 5012+ 基线、renderer 2910+ 基线、hub 仓 vitest 基线），新增票均带失败路径用例。
- **契约测试**：T1 双仓 `protocolSupports` 语义对齐；T2 映射表逐条；T5 作用域函数默认/隔离双态。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| T1 动分发层伤既有 RPC | 方法表 M3.0 只登记 1.2 基线（全部 minor=2），分发行为对 1.2 节点逐字节等价；契约测试锁既有错误形状 |
| T5 作用域化误伤默认 profile | 默认 profile 服务名**完全不变**；隔离 profile 才作用域化；双态测试 |
| T6 适配改动引入本地回归 | 本地全量 e2e + CI 三连绿才删 testIgnore；失败即回滚该票（其余票不裹挟） |
| 过夜自主无人裁决 | 用户级决策已预授权定格；技术争议以 Momus/oracle 结论为准；无法收敛时该票回滚不阻塞其余票 |
