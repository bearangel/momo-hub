## 1. 背景与问题

M2.1 path2 验收暴露分发链的最后一段断裂：**发布到 hub 的资源只有插件类会回填本地 hub 记账**（`ba7cce8f` 先例），agent/skill/mcp 发布成功后 `installed_packages` 无 `hub:{slug}` 行 → 快照构建器 `HubAccounting` 反查 miss → manifest `resources` 不携带 → **全新目标节点先装后落断链，unresolvedRefs 残留**。实测形态：superpowers 类 15 个 marketplace 源 skill 在全新 B 上 unresolved（path2 只因 B 有上轮遗留拷贝而未显形）。

镜像 catalog 自愈（M2.1 `84bfe37c`）只覆盖**内置 catalog 域**；私有/上传资源的分发仍依赖手工在目标逐个安装。M2.2 把「发布 → 记账 → 快照携带 → 目标先装后落」闭环推广到全部资源类型，并清偿累计打磨票。

## 2. P1 分发链闭环（主题）

### 2.1 发布记账回填泛化

**UC-P1-1** 任一类型资源（agent/skill/mcp/plugin）发布到 hub 成功后，本地 `installed_packages` 回填 `hub:{slug}` 记账行（幂等：同 slug 升版单行更新；`item_type` 限定删除不牵连同 slug 异类行——T15a-F1 纪律）。

- 机制：`ba7cce8f` 的 `recordPluginPublishAccounting` 泛化为 `recordPublishAccounting(type, slug, version, checksum)`，`hub:publishResource` 各类型分支统一调用
- 前提约束：发布语义 = 「本机已装此资源且愿意分发」——发布入口本就要求已装（资源库已装项才有发布钮），无额外语义
- 硬化（delta 终审 P3 并票）：回填失败不翻转发布回执（try/catch + warn——hub 上传已成功，记账缺行下次升版发布可自愈）

### 2.2 发布能力面核实

**UC-P1-2** 逐类核实发布链对「实际会出现的源形态」的覆盖，缺口补齐：

| 类型 | 源形态 | 现状 | 动作 |
|---|---|---|---|
| skill | marketplace 目录/上传 zip 装（superpowers 类） | M1 打包链=cachePath 目录整包 ✓；发布 UI 入口需核实对非 custom 源开放 | 核实+补缺 |
| agent | custom（上传/自建） | M1 C3「仅 custom 可发布」✓ | 不动 |
| mcp | npx 形态 | M1 支持 ✓ | 不动 |
| mcp | 本地 stdio（command 指本机二进制，如 `test`） | 不可移植 | **明示域外**（§5 已知限制） |
| plugin | dev/zip | M2.1 path2 已通 ✓ | 不动 |

### 2.3 镜像侧（零改动确认）

`installResources` 先装后落链（M1）已类型通用；`HubAccounting` 反查已按 `hub:` 前缀 + 类型过滤（delta 终审实证）。M2.1 catalog 自愈与 hub 资源补装**共存序**已由终审核定：resources 先装（硬失败中止）→ applyConfig 解析（catalog 自愈软失败）——本里程碑不动镜像侧。

### 2.4 端到端验收形态

**UC-P1-3** 真机全新 worker：A 发布私有 skill 集（superpowers 15 个）→ A 重发镜像 → 全新 B（无遗留拷贝）`unresolvedRefs` 中 `skill:*` 清零；逐条证据（hub catalog 数 / B installed_packages `hub:` 行 / manifest resources 段 / 回执 unresolved）落 qa-report。

## 6. 风险与红线

- **记账幂等/类型限定**：回填 DELETE 必须带 item_type（T15a-F1）；升版单行更新
- **发布回执不因记账失败翻转**（§2.1 硬化）
- **skill 内容标记兼容**：hub 安装链落 `.sha256` 标记（custom 判定），与 custom 内嵌判定面无冲突（M1 已定序）；回填行不参与该判定
- **P2 批消费面**：每票按 momo-feature-scope-rules 走消费面矩阵（尤其 P2-4 级联清理——成员引用面全枚举）
- 测试纪律：TDD + 变异验证；真机验收循 momo-acceptance（CDP 隔离实例）
