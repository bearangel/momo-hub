## 1. 背景与问题

M2.2 验收暴露一族版本取值链缺陷：**hub 资源「更新」回执成功但本地版本停留并误报「已是最新」（D3）**；**全新安装取旧版**（codegraph 2.0.0 vs hub latest 2.0.1，观察 O-1）。两症同族——latest 解析或升版链取值错误。分发链闭环（M2.2）让资源可达，但**到达的版本不对**，闭环价值打折。

另累计：worker 本机 failed 卡无 reason 通道（跨域接口留白）、activeWorkspace 漂移诱因未定位（验收 O-2）、六件评审锁面 Minor、测试基建债（agent-threads SIGSEGV / hookTimeout / monaco 噪声）、以及真机验收场景未沉淀为自动化回归资产。

## 2. P1 版本取值链修复（主题）

### 2.1 根因探查（先行裁定任务）

**UC-P1-0** 探查并裁定缺陷所在侧：
- studio 侧候选面：资源库「更新」链（版本比较/已装判定——「已是最新」误报点）、hub 目录消费（latest 字段解析/降序取值）、安装请求（显式版本 vs latest 缺省）
- hub 侧候选面：目录端点 latest 计算（多版本排序/version parse 语义）、按 slug 安装端点的版本选择
- 产出：根因定位报告（两侧取值链逐一对照，含真机 curl/DB 证据）；**裁定studio 修 / hub 修（v0.1.5）/ 双修**；hub 侧修走 tag v0.1.5 + pin 升级（T10b/T11b 先例流程）

### 2.2 修复

**UC-P1-1** 升版链语义修复：
- 「更新」= 取 hub latest 实际新版；本地已是最新时如实报告（不误报成功也不误报已最新）
- 安装缺省 = 取 latest（不取旧版）；已装旧版时「安装/更新」统一走版本前进
- 版本比较语义明确（semver 规范比较，非字符串字典序——若现状是字典序即根因之一）

**UC-P1-2** 真机全链验收：发布 v1 → 安装 → 发布 v2 → hub catalog latest=v2 → 「更新」→ 本地版本前进 v2 → 重镜像 → 目标补装取 v2（版本一致全链证据）。

## 6. 风险与红线

- **hub 侧改动纪律**：仅 v0.1.5 tag 最小修（latest 取值/安装端点版本选择），协议面不加字段则 pin 升级即可；任何超出即回报用户重批
- **版本比较语义变更**波及资源库全类型「更新/安装」面——消费面矩阵三锚先行（更新按钮/已装判定/安装链全部消费点）
