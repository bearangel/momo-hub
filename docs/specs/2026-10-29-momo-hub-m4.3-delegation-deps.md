# M4.3 委派依赖透传 — 设计规格与实施计划（合并稿）

- **状态**：已定稿（M4 探查 C3 事实 + M4.2 后协议基线 1.6.0/v0.2.0）
- **上游**：m4-roadmap §1 C3（已批准）
- **定位**：外派链的依赖语义收口。**核心 = leader 侧派发闸**（blocked 不 delegate）；透传字段仅展示/审计（worker 不消费——语义裁定：dependsOn 是 leader 本地任务 id，跨节点无意义）。

## 1. 事实基线（探查定案）

- 外派三入口：`submitRoutedTask`（`dispatch-submit.ts`，hub:taskDelegate 直通道 `ipc.handlers.ts:91-103`）、`retryDispatch`（`delegation-sync.ts:385` 附近）、批量行外派路径（CreateTaskDialog M3.3 裁定**不解析 `::`**，测试锁死）。
- M3.3 四闸（executor peek/retryDispatch 本地任务/move/start）不含外派链——**外派任务绕过依赖闸**（缺口本票核心）。
- 协议 `DelegationTask`（hub `src/delegation.ts:20-27`：title/prompt/agentSlug/permissionTier）无依赖字段；hub `parseDelegationTask` 白名单（`delegations.ts:109-126`）；brief 不持久化只随 task.assigned 事件过（:274-277）。
- studio `DelegationTaskBrief`（`dispatch-submit.ts:53-58`）；`SubmitRoutedTaskInput` 已有 description（:35）。

## 2. 设计

### 2.1 协议 1.7.0（hub 仓，版本 0.3.0——minor 对齐惯例）

`DelegationTask` 增可选 `dependsOn?: string[]`（≤50 项、每项 ≤128 字符；透传**不校验存在性**——leader 本地 id 对 hub 无意义）；task.assigned 事件随 task 对象透传；PROTOCOL_VERSION → '1.7.0'（注释：外派依赖元数据，向后兼容可选字段）；METHOD_REQUIRED_MINOR 零登记（纯可选字段）。

### 2.2 hub 实现

parse 白名单扩 dependsOn（形状校验：string 数组 + 上限，非法整包拒 400——沿 manifest version? 三格模式）；task.assigned 事件载荷随 task 透传（既有结构零改动——task 对象整体携带）；测试：透传三格（缺省/在场/非法）+ 既有 brief 锁零破坏。

### 2.3 studio 实现

1. **leader 侧派发闸（核心）**：三入口前置 blocked 检查——`submitRoutedTask` 提交前、`hub:taskDelegate` 直通道、`retryDispatch` 委派重派路径；blocked → 人话拒绝「存在未完成依赖（T-x，T-y）」（与 M3.3 四闸同文案单源）；复用 M3.3 blocked 派生（relations/unsatisfiedDeps）。
2. **外派行 `::` 解析启用**：CreateTaskDialog 外派路径解析依赖语法（M3.3 锁死测试按语义升级——外派行建链后任务自身 blocked，dispatch 受闸管制）。
3. **brief 透传**：`DelegationTaskBrief` + `dependsOn?: string[]`（dispatch-submit 组装时从任务行带出）；委派卡 leader 分支显示「依赖 T-x」摘要（blockedBy 同源数据，非新 UI 形态）。
4. **worker 侧零消费**（注释锚定语义裁定）。

### 2.4 测试与验收

- hub：透传三格 + 白名单上限拒收。
- studio：三入口闸（blocked 外派被拒人话/依赖完成放行）+ 外派行 `::` 建链（M3.3 语义升级测试改写）+ brief 带出 + 委派卡摘要；全量绿（**--maxWorkers=2 全程**）。
- 真机验收从简（本票无 hub 行为变更面——闸为本地逻辑、透传为展示）：e2e 增补一条（task-dependencies.spec 场景：外派 blocked 任务 → 派发被拒 toast）替代真机验收，oracle 终审照常。
