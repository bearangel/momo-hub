## 1. 背景：盘点与核实结论

M2.4 终审后对 2.x 全部遗留做了一次证据级盘点（A 真缺陷 / B 能力缺口 / C 技术债）。其中 4 条历史 concern 经代码核实**全部出栈**（附录 A 留证，防下一轮重复盘点）：

- keychain 残留（device token）→ **FIXED**（断开并忘记 / 换 hub 地址 / 重新 enroll 三条路径均已 `clearDeviceToken`）
- hub 绑定 `*:18787` → **NOT-A-DEFECT**（18787 仅验收覆盖；产品默认 8787；通配绑定是 hub 仓硬化项）
- B 窗口重载 → **FIXED**（底层 D1 已由 `workspace:listChanged{reason:'mirror-applied'}` 修掉；全仓仅一个 BrowserWindow、无主窗口 reload 路径）
- 凭证截断 → **NOT-A-DEFECT**（device token 不出主进程、不进日志；hub 只存 sha256；唯一明文是启动横幅且为全值未截断）

核实后 A 组剩 5 项（A5 建议关闭，故实修 4 项）。A6 经探查确认**可零 hub 改动实现**（复用已在用的 `hello.onlineNodes` 快照 + 主进程 `presenceSeed`）。

## 2. 核心裁定

| 裁定 | 结论 |
|---|---|
| **R1 只修用户可见的谎与缺** | M2.5 只做「用户会看错/看不到」的四项：角标不播种、下载失败无口味、双前缀、节点清单无补拉。不做架构改良 |
| **R2 播种是「拉取后一次性 replace」，不是新增推送通道** | 角标播种只发生在目录**成功**加载后（`degraded=false && stale=false && notEnrolled=false`）；不加轮询、不加定时器。M2.3 D7 的「无事件不复活」锁需**显式修订**为「未拉取时如实；拉取后按目录」 |
| **R3 错误文案单点归属** | 每个错误只有一个前缀来源；`TypePageShell` 遇到已带业务前缀的 message 不再叠加 |
| **R4 节点补拉走 studio 单仓** | 新 IPC `hub:getNodes` 读主进程 `presenceSeed`（`hello.onlineNodes` 快照 + presence 事件增量维护）；**不改 hub、不改协议 semver** |
| **R5 A4 撤回：镜像不做按版本升级** | 取证：`SnapshotResourceRef` 仅 `{type,slug}`（`momo-hub/src/groups.ts:155-158`），`loadHubAccountingSet()` 只返 slug 集（`hub/accounting.ts:25-36`）——**快照不含目标版本**，「升级到哪个版本」无数据来源。要做需 ①manifest 增 `resources[].version`（协议扩展）或 ②应用时逐资源查目录（给已装路径引入网络）。二者都超本期边界 → 记 **B13 / M3** |
| **R6 B 组 12 项一次性关闭，迁 M3 清单** | 本期写「已关闭/已迁移」决议，附理由；M2 系列此后不再开新期 |

**裁定结果（2026-10-28 用户批准）**：
- **D-A4 = 撤回（2026-10-28 二次裁定）**：先按「做」批准，落地前取证发现快照清单不含资源版本（见 R5 取证）——不是缺陷而是协议表达能力限制；移出本期，记 B13/M3
- **D-A5 = 关闭**：readonly 标记不持久化，记为设计边界（重启后仍有「只读约束段 + HITL 超时拒」双保险；持久化归 M3 权限子系统）

## 4. 契约与边界

### 4.1 角标播种（A1）

```ts
// renderer/src/stores/resource.store.ts
/** 目录成功加载后一次性播种 hub 更新表：key=`${type}:${slug}` */
seedHubUpdates(entries: Array<{ type: ResourceType; slug: string; version: string }>): void;
```

- 输入来源：hub 资源库列表结果（`listHubMarketplaceItems` 返回的条目 + 本地已装账表）
- **仅当** `degraded === false && stale === false && notEnrolled === false` 时 replace；否则**保持现状不动**（不误清）
- 已装比较用 `version-compare` 单源（`target > installed` 才入表）
- 触发点：hub 页首次加载完成 / 手动刷新完成
- 事件路径（`resource.published` 增量）**保留**——播种是「基线」，事件是「增量」

### 4.2 下载失败人话（A2）

```ts
// electron/src/main/util/network-error.ts（新）
/** 网络错误 → 用户可读中文；无法归类时返回「网络请求失败」 */
export function describeNetworkError(err: unknown): string;
```

映射表（示例，实现时补全）：`ENOTFOUND/EAI_AGAIN`→无法解析域名；`ECONNREFUSED`→连接被拒绝；`ETIMEDOUT/AbortError`→超时；证书类→证书校验失败；`404`→资源包不存在（可能已下架）；`403/401`→无权限下载。

- 用在 `marketplace/installer.ts` 下载出口：`throw new Error('下载资源包失败：' + describeNetworkError(err))`；原文 `logger.warn('下载失败', { slug, error })`
- **禁止**把原始 `TypeError: fetch failed` 直接上抛到 UI

### 4.3 单前缀（A3）

- 规则：`TypePageShell` 拼接「加载失败：」前判断 message 是否已以已知前缀开头（`导入失败：`/`安装失败：`/`下载资源包失败：`），是则原样展示
- 已知前缀清单集中在一个常量（避免下次再加前缀时漏改）

### 4.4 节点补拉（A6）

```ts
// preload / types.d.ts
hub.getNodes(): Promise<Array<{ nodeId: string; nodeName: string }>>;  // 主进程 presenceSeed 快照（含本机）
```

- 主进程：读 `presenceSeed`（已有：hello 快照 + `node.online/offline` 增量维护），**只读快照，不新增 hub RPC**
- renderer：`hub.store` 增 `pullNodes()`，面板挂载 / 重连（`hub:getStatus` 后）调用，`replace nodes[]`；`hub:nodePresence` 增量订阅保留
- 契约：`hub:nodePresence` 载荷的 `at` **已随 `...p` 透传**（`hub/index.ts:461-464`；`types.d.ts:2653` 已声明）——本期无需改；只在种子重播（`hub:getNodes`）返回值里一并带上 `at?` 保持一致

### 4.5 镜像升级（A4，**已撤回**）

**本期零改动**。既有 `mirror-applier.ts:402`（记账命中跳过）、`:404`（本机已在场跳过）保持原样。

移到 M3 的前置条件（写进 B13）：manifest `resources[]` 增可选 `version`（协议 semver minor 扩展 + 向后兼容：缺省=不限版本，保持今天语义）→ 才谈「按快照版本对齐」。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 播种与 M2.3 D7 锁冲突 → 复活/误报 | 播种仅「成功目录」触发；`degraded/stale/notEnrolled` 一律不动；同步修订 D7 断言并新增「拉取后按目录」正向锁 |
| 播种在大目录上造成渲染抖动 | 一次性 replace（单次 setState），不做逐条 |
| `describeNetworkError` 归类错误导致误导 | 未命中分类时回退「网络请求失败」，绝不猜具体原因 |
| 节点补拉与事件竞态（拉取返回旧快照覆盖新事件） | `pullNodes()` 结果与现有事件合并取并集（拉取只增不删，删除仍由 offline 事件负责）——**明确此语义** |
| 改 D7 断言削弱既有锁 | 修订而非删除：保留「无拉取时如实」断言，新增「拉取后按目录」断言 |

## 7. 已知限制（本期不修）

- readonly 即时拒标记进程内易失（**决议：设计边界**，双保险在）
- provider 失败卡面为主文案（原始 401 仅日志，M2.4 已裁定）
- 无终态 final 事件时「未知错误」（真兜底）
- hub 单点 / http 明文需 TLS 反代（运维约定）
- e2e CI 首跑需推送后实测（预案在案）

## 8. 验收方式

- 单测：每票 TDD；A1 需锁「未拉取/成功拉取/degraded/stale」四态；A6 需锁「拉取+事件竞态并集」
- 真机：UC-P1-1/2/3、P2-1/2、P3-1
- 收尾：alpha.35×3 + CHANGELOG（含 B 组关闭决议）+ oracle 全分支终审
- **冻结判据**：A 组剩余 3 项清零（A1/A2+A3/A6）+ B 组 13 项决议成文 + 收尾合并 → M2 系列关闭，M3 重新拆期
