# M3.4 资源生命周期与版本对齐 — 设计规格与实施计划（合并稿）

- **状态**：已定稿（资源面全图探查回填）
- **上游**：roadmap M3.4（B10/B12/B13）；M3.0-3.3 已交付
- **定位**：M3 收官期。协议 minor **1.5.0**：manifest `resources[].version?`（B13）+ 撤回/下架（B12）+ 目录事件增量合并与持久化修订号（B10）。

## 1. 事实基线（探查定案）

- 协议包 = hub 仓根 `src/`（studio pin `#v0.1.8`，`electron/package.json:102`）；`SnapshotResourceRef {type,slug}`（`src/groups.ts:155-158`），**未知字段剥除点 = resourceRefsFrom :249-258**（逐项重建字面量 :255——不加透传即静默剥掉）；hub mirror 只按 snapshotId 转发（**resources[] 对 hub 透明**）。
- hub 资源面：publish 任何注册节点（HTTP Bearer）；`resource_versions` PK(slug,version) 版本不可变三锁；**无 DELETE/PUT/PATCH、无 deleted/deprecated 列**（db v1-v6）；catalog `buildHubCatalog` **`updatedAt` 每次请求现打（resources.ts:395）——非持久化修订号**；版本行空→不成项 :371-372；下载端点天然保历史版本；blob 内容寻址孤儿不回收。
- studio：builder 四域只产 {type,slug} + type+slug 去重（`snapshot-builder.ts:477-485`）；**记账行 `hub:{slug}` 自带 version**（`loadHubAccountingSet` 现只回 slug 集——B13 版本源需扩）；applier `installResources :391-420` 对 hub 永装 latest（`installResource` 缝 `:78`）；hub-install 判定矩阵 `:434-441` + alreadyLatest semver `:456-471`。
- B10 缺口具体化：事件通路只进 renderer 角标表（`hub/index.ts:539-545`→`hubUpdates`），**主进程 HubCatalogSource 缓存（TTL 5min/退避 60s/lastGood，`momo-hub.ts:205-370`）完全不感知**——新发布最长 5min 不可见。
- roadmap 裁定（:70）：撤回只影响目录可见性、已装保留、下载端点保留历史版本。

## 2. 设计

### 2.1 协议 1.5.0（hub 仓，版本 0.1.9）

1. `SnapshotResourceRef` + `version?: string`（groups.ts:155-158）+ resourceRefsFrom 透传（isValidHubVersion 校验，非法 400；缺省合法——1.4 旧 manifest 零变化）。
2. `HubCatalog` + `revision: number`（**必填新字段**——旧 hub 不会发它、新 studio 消费时容错缺省 0；对 1.4→1.5 老新兼容无碍：字段新增非破坏）。
3. `EVT.resourceUnpublished` + `ResourceUnpublishedEvent {slug, by, at}`。
4. `METHOD_REQUIRED_MINOR`：本组全部为**可选字段/事件**，无新 RPC 方法——**无门槛登记**（事件与字段对旧节点天然宽容：未知事件忽略、未知字段剥除）。

### 2.2 hub 实现（packages/hub）

1. **v7 迁移**：`resources` + `unpublished_at INTEGER NULL`（墓碑）；新表 `hub_meta(key TEXT PRIMARY KEY, value TEXT NOT NULL)` + 初始化 `catalog_revision='1'`。
2. **发布事务扩展**：publish 成功 → 清墓碑（同 slug 重发布恢复可见）+ `catalog_revision++`（同事务）。
3. **撤回端点 `POST /resources/unpublish`**（Bearer，与 publish 同信任模型——任何注册节点；leader-only 治理记为设计边界延后）：body `{slug}`；404（无此资源）；幂等（已撤回再撤=200）；效果 = 墓碑置位 + revision++（同事务）+ `resource.unpublished` 广播；**不删版本行/blob**（下载历史保留，roadmap 裁定）。
4. **catalog**：过滤 `unpublished_at IS NOT NULL`（:371-372 同位点）；响应带 `revision`（读 hub_meta）。
5. 测试：撤回全链（目录消失/下载仍在/幂等/republish 恢复/revision 单调）；publish 清墓碑；manifest version? 三格（缺省/在场/非法）；protocol-resources 剥除断言范围显式排除 version；HubCatalog revision round-trip。

### 2.3 studio 主进程

1. pin `#v0.1.9` + protocol-pin 测试。
2. **B13 版本对齐**：`loadHubAccountingSet` 扩为含 version（type→slug→version）；builder 收集点写入 `version`（**记账版本 ≠ 目录 latest 时写记账版本——快照定型语义**，注释言明）；applier `installResource` 缝增可选 `pinnedVersion` → `installHubPackage` 增可选钉死参数：fresh 下载该版本（404 → 记 unresolvedRefs 不中止，沿 stale 跳过模式）；alreadyLatest 判定对 pinned（installed ≥ pinned → alreadyLatest；installed < pinned → 升级到 pinned——**镜像升级语义，M2.3「不升级旧版」边界由此打开**，CHANGELOG 明示）。
3. **B10 增量合并**：`createHubCatalogSource` 增 `applyPublishedEvent(evt)` / `applyUnpublishedEvent(evt)`（事件 upsert/剔除 cache 与 lastGood items；revision 未知不伪造）；`hub/index.ts` onEvent 增 resourceUnpublished 分支（桥 renderer + 调 catalog source 剔除）；resource.published 同样接 catalog source（消 5min 盲窗）。**全量拉取仍为权威路径**（TTL 不变），事件只做即时性——注释言明分工。
4. **撤回客户端**：`unpublishHubResource(slug)`（HTTP Bearer，momo-hub.ts）+ IPC `hub:unpublishResource`。
5. 测试：记账版本源三态（无记账→latest 兜底/记账旧/记账新）；applier pinned 下载与 404 跳过；事件合并（published 即时可见/unpublished 即时消失/与 lastGood 一致性）；hub-provider 缓存三锁扩展；unpublish 客户端。

### 2.4 studio renderer

1. 资源卡（**仅 hub 来源**——消费面矩阵：builtin/custom/marketplace 卡零变化）动作菜单增「下架」armed-confirm（uninstall 模板；确认文案含 slug 与「已安装节点不受影响」）→ `ipc.hub.unpublishResource` → 成功 toast；404 → 「资源不存在或已撤回」。
2. `resource.store`：消费 `resource.unpublished` 事件（hubUpdates 键清除 + 若目录缓存含该条目本地乐观剔除——主进程已剔，renderer store 列表源于 IPC 拉取，事件到时刷新一次 load()）。
3. 测试：菜单门控（仅 hub 来源卡）/确认流/事件消费/store 刷新。

### 2.5 测试与验收

- 真机验收：UC-1 发布→目录即时可见（<5s，不待 TTL）；UC-2 下架→目录消失+另一实例事件同步剔除+下载历史版本仍可装（直调安装链 pinnedVersion=历史版本）；UC-3 镜像补装按 pinned 版本（worker 缺旧版→装快照钉死版）；UC-4 已装旧版节点收到含新 version 的快照→升级到 pinned；UC-5 撤回幂等+republish 恢复；UC-6 旧 hub 1.4 + 新 studio（pin v0.1.9 客户端连旧 hub）→ 下架按钮 404 人话、目录无 revision 字段容错（门控：不按 revision 判变）。
- oracle 终审 → alpha.40 + CHANGELOG → PR + CI 绿 → 合并 → **M3 系列收官冻结**。

## 4. 风险

| 风险 | 缓解 |
|---|---|
| revision 字段旧 hub 不发 | studio 容错缺省 0 且**不以此判变**（仅展示/日志）；权威失效仍靠事件+全量拉取 |
| 事件乱序（unpublished 先到 published 后到） | catalog source 事件合并幂等（upsert/剔除按 slug 终态）；全量拉取自愈 |
| pinned 版本已被撤回（下载 404） | 记 unresolvedRefs 跳过不中止（stale 模式）；报告可见 |
| 镜像升级语义翻转（M2.3 边界打开） | 仅当 manifest 带 version 才升级（无 version=旧 latest 语义不变）；CHANGELOG 明示 + 验收 UC-4 锁 |
| 下架 UI 越权面 | armed-confirm + 仅 hub 来源卡 + 确认文案明示影响面（消费面矩阵） |

## Review Focus（呈 Momus）

1. revision 必填新字段的兼容主张（旧 hub 不发→studio 容错；非破坏论证）。
2. 撤回信任模型（与 publish 对称的任何节点）与 leader-only 延后的边界记录充分性。
3. pinned 升级语义翻转的触发面（仅带 version 的 manifest）与 M2.3 边界关系。
4. 事件合并幂等性与全量拉取的分工（即时性 vs 权威性）表述。
5. 剥除断言范围调整（protocol-resources.test.ts:96 排除 version）不弱化原锁。
6. 消费面矩阵（下架入口仅 hub 来源卡）。
