# M3.1 HITL L2 远程代答 — 设计规格

- **状态**：已定稿（双仓探查回填）
- **日期**：2026-10-28
- **上游**：roadmap §2 M3.1（已批准）；M3.0 已交付（协议协商前置 = 本期能力门槛的地基）
- **定位**：补齐 HITL 链路最后一环——worker 写授权等待时，**leader 远程批准/拒绝**。协议 minor 1.3.0。

## 1. 目标与非目标

**目标**：leader 在委派卡上一键代答（approve/deny），worker 侧复用既有本机授权原语解除等待；全链路幂等、越权双校验、决策留痕。

**非目标**：不做留言注入（message 仅审计/UI 展示，不注入子进程）；不做 waiting 的周期性 sweeper（卡死回收仍走 onNodeOffline→interrupted 既有路径）；不改 worker 本机代答卡（SandboxNotice/InFlightPanel 原样）；不做 `task.waiting` 事件（见 §3.4 裁定）。

## 3. 设计

### 3.1 协议面（hub 仓，版本 0.1.7，PROTOCOL_VERSION → '1.3.0'）

**新 RPC `task.answer`**（leader-only）：
- Req：`{taskId: string, decision: 'approve' | 'deny', message?: string(≤512)}`
- Res ok：`{disposition: 'granted' | 'denied' | 'stale'}`
- Res err（RpcErrorCode 新增/复用）：`not_found`（taskId 无记录）/ `not_waiting`（status≠waiting，message 含当前状态）/ `forbidden`（非同组 leader）/ `node_offline`（worker 离线，对齐 delegate 裁定①）/ `node_unsupported`（worker minor<3，载荷带 worker 版本）/ `answer_timeout`（worker 10s 未回）。
- `message` 语义：仅审计与 leader 侧展示；**不注入子进程**（approve 走 covered 轮询原地重执行、deny 走标准拒绝文本——两条既有路径均无注入点，一义一名不扩义）。

**`waiting` 一等态**（roadmap 明文）：
- 迁移表增：`running→waiting`、`waiting→running|done|failed|cancelled|interrupted`（36 对矩阵 → 45 对，扩容测试）。
- **触发规则（acceptReport 改造）**：report `status:'running'` 且 `progress.kind==='waiting-input'` 且 row.status=running → 迁移 waiting（同时照常 forwardProgress）；row.status=waiting 时同类上报 = 进度拍（账本不动）；report 无 kind 且 row.status=waiting → 迁移回 running。终态上报自 waiting 合法（表已含）。
- 语义闭环：approve/deny 后 worker 下一拍无 kind 自动回 running——**hub 不在 answer 时直接迁移**，账本状态由 worker 上报驱动（单一真相源不破）。

**决策列（db v6 迁移，追加纪律）**：`answered_by TEXT NULL / answer_decision TEXT NULL('approve'|'deny') / answer_message TEXT NULL / answered_at INTEGER NULL`；`TaskRecord` 扩四字段（键集锁 `:529` 同步更新）。

**事件 `task.answered`**（定向 by_node_id，与 progress/terminal 同向）：`{taskId, decision, by: nodeId, disposition}`——leader UI 即时反馈。**不做 `task.waiting` 事件**（roadmap 偏差，理由：leader 等待展示已有 task.progress kind 通道且被 `delegation-sync.test.ts A-10~A-14` 锁死；双信号必漂移——momo-boundary-rules「一义一名」。waiting 状态经 task.list/键集对账即可见）。

**能力门槛**：`METHOD_REQUIRED_MINOR[RPC.task.answer]=3` 显式覆盖（fromEntries 后追加）；hub 转发前查 worker `minorOf(session.peerProtoVer)≥3`，否则 `node_unsupported`（M3.0 管道首次实战）。

### 3.2 hub `task.answer` handler 流程（`delegations.ts` 新 handleAnswer）

1. 守卫层：提取器 taskId→`SELECT group_id FROM delegations WHERE task_id=?`（cancel 模式）→ `checkGroupRole`（同组 leader，**校验一**）。
2. handler：getTask → not_found；`row.status !== 'waiting'` → not_waiting；handler 内**重查组与 leader 再核一次**（remote-view 双校验先例 `remote-view.ts:150-152`，**校验二**）。
3. worker 在线检查（registry）→ node_offline；worker minor≥3 → node_unsupported。
4. 转发 `task.answer` RPC 给 target（**hub→worker 定向 req**，worker res `{ok, disposition, sessionId?}`）；per-forward 10s timer（view 模板：unref、可注入、离线即时结算不占窗）→ answer_timeout。
5. worker res ok → UPDATE 决策四列 + logger 审计行（`委派已代答`）+ emit `task.answered` 给 by_node_id + res `{disposition}` 给 leader。
6. 幂等：重复 answer 允许（worker 无 pending 时自报 `stale`）；决策列记最新，logger 逐次。

### 3.3 studio worker 侧（electron）

- `delegation-wire.ts`：TASK_WIRE/转发 RPC 名 + 载荷类型（`TaskAnswerForward{taskId,decision,message?}` / `TaskAnswerWorkerRes{ok, disposition, sessionId?}`）。
- `hub/index.ts handleHubRequest` 增 `task.answer` 分支（mirror.apply 模式）：
  - `delegationStore.get(taskId)` 无记录 → `{ok:true, disposition:'stale'}`（worker 无此委派，幂等口径）。
  - sessionId → `listPendingWriteBlocked(sessionId)` 空 → `stale`（已答/已超时清扫）。
  - **approve**：聚合全部 pending 条目的 dirs → `grantWriteDirs('session', sessionId, dirs)` 一次 + 逐条 `clearPendingOnGrant('session', sessionId, entry.signal.dirs)`。
  - **deny**：deny 广播（`handleDenyWrite` 同构广播）+ `clearPendingOnDeny(sessionId, [])`（空 dirs=整会话）。
  - res `{ok:true, disposition:'granted'|'denied', sessionId}`。
- 依赖注入沿用 hub/index.ts 现有装配（grant/deny 原语与 store 已在装配域）。

### 3.4 studio leader 侧

- IPC 三层：`types.d.ts` `taskAnswer(input: {taskId, decision, message?}): Promise<{disposition}>`（taskCancel 模板 `:3090`）→ preload `invoke('hub:taskAnswer')` → `ipc.handlers.ts` `hubRequest(RPC.task.answer, input)`（`hub:taskCancel :100-104` 模板）。
- **门控**：新建 `renderer/src/lib/hub-capability.ts` `hubSupportsMinor(hubProtoVer, required)`（镜像 protocolSupports 语义，含非法串 false）+ **双侧契约测试**（与 electron 侧 protocolSupports 同一组字符串 fixture 断言等值——error-prefix 双侧模式）。
- `DelegatedTaskCard`：等待态 && leader 视角 && `hubSupportsMinor(hubProtoVer,3)` → 动作菜单增「批准节点写入」「拒绝节点写入」两项（armed-confirm，cancel 模板）；成功 toast + 角标状态经 `task.answered` 事件刷新；`RpcRemoteError` 且 code ∈ {unsupported_method, unknown_method, node_unsupported} → toast「节点或 hub 版本过低，无法远程代答」。文案级小改（两个菜单项 + toast），无布局变更（P2 豁免口径，验收留截图证据）。
- `delegation-sync`：onEvent 增 `task.answered` 处理 → progress kv 写 `answered:{decision, at}`（`DelegationProgressEntry` 扩可选字段，解析规则沿 waiting 的 `=== true` 保守模式）；六态映射增 `waiting`（来自 task.list TaskRecord.status）。卡片等待角标逻辑不动（仍走 progressEntry.waiting）。
- worker 侧 `onEvent` 不需新分支（answer 是 RPC 转发非事件）。

### 3.5 权限与安全

- 代答权 = **同组 leader**（提取器守卫 + handler 复核双校验）；跨组/非 leader → forbidden（同码防探测）。
- by_node_id 只作事件投递目标（既有语义）；代答权锚 `delegations.group_id → groups.leader_node_id`（与 cancel 一致）。
- 决策留痕：决策四列（最新）+ logger 逐次审计行；测试锁定（delegations 审计测试模式 `:717-768`）。

## 4. 测试与验收面

- **hub 单测/集测**：45 对迁移矩阵；acceptReport 三新规则（running+kind→waiting、waiting 同类=拍、waiting 无 kind→running）；handleAnswer 全错误码路径 + 双校验 + 幂等（二次 answer→stale）+ worker minor 守卫 + 转发超时（注入短 timer）；`task.answered` 事件形状；TaskRecord 键集锁更新；minor 门槛三态（1.2 调 task.answer → unsupported_method{method,requiredMinor:3}，1.3/1.9 正常）。
- **studio 单测**：worker 分支（approve 聚合多 pending dirs、deny 整会话、无委派/无 pending→stale）；leader IPC 链（RpcRemoteError 透传 code）；sync `task.answered` kv 与 waiting 状态映射；card 门控（hubProtoVer 三态：null/1.2/1.3）；hub-capability 双侧契约。
- **真机验收**（双实例 + hub 0.1.7）：UC-1 leader 批准 → worker 子进程原地重执行、卡角标消失、决策列留痕；UC-2 leader 拒绝 → worker LLM 收拒绝文本继续；UC-3 重复代答 → stale 口径；UC-4 跨组 leader 代答 → forbidden；UC-5 状态非 waiting 代答 → not_waiting；UC-6 旧 hub（0.1.6 实例）+ 新 studio → 按钮隐藏 + 手动调用 toast 版本过低（真机做 0.1.6 hub 二进制，可行——hub 仓 git worktree checkout v0.1.6 构建）。
- oracle 终审 → MERGE READY → hub v0.1.7 tag → studio pin 升级 → PR → CI 绿 → alpha.37 + 账本 → 冻结。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| waiting 态引入账本/事件双源漂移 | 状态唯一由 worker 上报驱动（hub 不在 answer 时迁移）；leader 展示仍走 progress kind（单信号） |
| 键集锁/矩阵扩容破坏面大 | 锁更新与功能同 commit；先跑全量再收口 |
| worker 收到 answer 时 pending 已 TTL 清扫 | stale 口径幂等返回，不报错 |
| 转发超时与 worker 慢处理竞态 | view 模板 per-pending timer；超时不改账本，leader 可重试 |
| renderer 门控助手与协议包语义漂移 | 双侧契约测试同 fixture 断言等值 |
| UI 无人预览（过夜自主） | 文案级最小改动（两菜单项+toast，无布局）；验收截图留证 + oracle 复核 |
