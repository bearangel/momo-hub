# momo-hub M2.1 · 工作组 IA 重分配与统一任务模型设计

- 日期：2026-10-26
- 状态：待评审
- 上游：`2026-10-24-momo-hub-m2-distributed-workgroups.md`（M2 已实现待合并，本设计基于其全部能力）
- 视觉合同：`momo-studio/.omo/previews/hub-ia-fullapp.html`（全窗 6+1 屏，明暗双主题，2026-10-26 用户批准）
- 实施基线：M2 两分支（hub `feat/m2-workgroups` @ v0.1.2 / studio `feat/hub-m2` @ 0e661cbc）合并后切枝；分支顺序在实施计划中裁定

## 1. 背景与动机

M2 真机验收（21/27 → P1×2 修复后全过）暴露四类体验问题，用户实测后确认：

1. **协作面错置**：工作组/镜像/委派/查看全部嵌在「设置 → 节点互联」页内层层展开；远程工作空间回放被 640px 卡在设置表单里。设置域应放配置，工作流应在主工作面。
2. **两套任务域的选择税**：若按 M2 原样加「任务池」，用户每次建任务都要先答「看板还是任务池」。裁定：执行位置是路由决策，不是任务分类。
3. **HITL 缺信号**：worker 侧 agent 等确认时（写授权 pending / 主动提问），leader 只见进度停滞，无「等待节点确认」状态；且无超时保护，存在永卡 running 风险。
4. **D2 空态困死**：新设备 0 工作空间时无法到达 enroll 入口（M2.1 票首项）。

## 2. 目标 / 非目标

### 目标

- 统一任务模型：一个任务域、一个创建入口、路由三选（本机 / 组内调度 / 指定节点）
- 工作组成为一等主视图（活动栏第 6 项）：编队监控台（成员/presence/负载/在跑任务/查看/组操作）
- 看板升级：本地 + 外派任务统一卡片混排；新建任务弹窗带路由字段与批量模式
- HITL 最小核：任务书权限档位 + 执行端就地确认 + 超时自动拒 + waiting-input 进度信号
- 设置·节点互联瘦身为纯配置；D2 由工作组视图空态就地接入治愈

### 非目标（YAGNI，本期不做）

- **Layer 2 远程代答**：确认请求经 hub 回传 leader 代答——双向 RPC + 超时语义复杂，M3 独立立项
- **任务源集成**：插件/cron/外部 TODO 拉取——多元入口生态问题，不在互联域预留任何位置（RM-IA1 裁定：未来经插件/定时任务等系统接入统一任务管道）
- **组级共享记忆**：M3b+ 独立 spec
- **负载自报协议**：hub 协议零改动，调度 v1 用 running 计数代理指标
- **多组深度操作面**：组列表可见、按组切换操作（MC6 语义不变）

## 3. 核心裁定（UC1-UC9）

| # | 裁定 | 理由 |
|---|---|---|
| UC1 | **一个任务域**。执行位置是任务的路由属性 `routing ∈ {local, group, node}`，不是任务分类 | 消除选择税；调度器存在的意义就是替用户答「谁来跑」 |
| UC2 | **看板=唯一创建入口**（新建弹窗含路由字段+批量模式）；工作组视图=纯监控台，无创建入口（callout 引导回看板） | 两个创建入口=两套任务感的源头 |
| UC3 | **路由守门**：工作空间未入组镜像 → 路由区只显示「本机」（不出灰选项、不出错） | 不出错、不困惑；镜像先行的既有语义 |
| UC4 | **调度 v1 = leader 端 least-busy**：候选=组成员 ∩ 已镜像该工作空间 ∩ 在线；排序=各节点活跃委派 running 数升序；无候选 → 任务留待处理列+人话提示 | hub 协议零改动（task.list 已有数据）；负载代理指标够用 |
| UC5 | **HITL 三层**：L0 任务书权限档位（只读 / 沙箱全权 / 执行端确认）；L1 执行端就地确认+超时自动拒（默认 15 分钟，可配）；L1b waiting-input 进度事件（`task.progress` 载荷加 `kind` 字段，向后兼容）。L2 远程代答 M3 | 现有原语（写授权等待/中途补充/委派会话=普通会话）已覆盖暂停与恢复，缺的只是信号与超时 |
| UC6 | **查看全宽化 + 空间选择器**：入口=节点卡「查看」/侧栏成员行眼睛；选择器列目标节点自己的空间（consent 授权即可看，与镜像无关；已镜像空间带徽标）；选定后主区整体替换为四页签只读视图 | 查看是读节点实况不是读镜像副本；640px 内嵌是容器错位 |
| UC7 | **设置·节点互联瘦身为纯配置**：连接（地址/凭证/节点名）+ 隐私与受控（consent/接受委派/并发上限）+ 迁移说明卡。组卡/镜像/委派/查看四块全部迁出 | 配置在设置、工作流在工作面 |
| UC8 | **D2 治愈**：工作组视图未接入空态提供「接入 hub」就地引导；接入流程不依赖工作空间存在 | 新设备零前置 |
| UC9 | **委派向导退役**：DelegationWizard 从组面板撤下；「指定节点」高级路由吸收其能力（选组内成员+任务书+权限档位） | 统一模型下向导是第二创建入口 |

## 5. 数据与主进程设计

### 5.1 路由字段落点

- 任务域扩展：任务创建载荷加 `routing: { mode: 'local'|'group'|'node', groupId?, targetNodeId? }`（存储层落 hub 域 kv 侧表或任务表扩展列——实施计划定，原则：不破坏既有 #T 任务管道）
- `local`：走既有本地任务创建路径，零变化
- `group`：创建即入待处理；leader 端调度器择节点后走**既有委派管道**（task.create：任务书+目标节点+权限档位），并在本地看板建立「外派卡投影」（taskId↔delegationId 映射存 hub 域）
- `node`：同 group 但跳过调度，目标锁定指定成员
- 取消/失败改派：外派卡操作菜单提供「取消」（走既有 cancel）；失败外派卡提供「重派」（复用 routing 重走管道）

### 5.2 调度器（leader 端，新模块）

- 输入：任务（workspaceId + routing.group）+ 组成员快照 + 各节点活跃委派计数（task.list 数据）
- 选择：在线 ∩ 已镜像该空间 → running 计数升序 → 次序稳定（nodeId 字典序打破平局）
- 触发时机：任务创建时即时调度；无候选 → 待处理+提示（不排队轮询——YAGNI）
- 并发守卫：leader 自身并发上限沿用全局 maxConcurrentTasks；worker 侧守卫沿用既有 maxConcurrent（超限 declined 人话回传）

### 5.3 HITL 落地

- **L0 档位**：任务书载荷加 `permissionTier: 'readonly'|'sandbox'|'confirm'`；worker 端 delegation-runner 按档位预配：readonly=只读工具集+不授写授权；sandbox=预授予镜像工作空间目录写授权；confirm=沙箱外请求不自动拒（等待）
- **L1 超时**：delegation-runner tick 检测回合等待态（写授权 pending / 无输出且存在未答请求）持续超阈值（默认 15 分钟，设置可配）→ 主动注入 write-grant-denied + steer「用户不在场，请保守处理或结束任务」
- **L1b 信号**：`DelegationRunPorts` 新增 `sessionWaiting(sessionId): { waiting: boolean; summary: string } | null`（生产实现挂在 RouterService 回合状态）；tick 检测到等待 → 进度拍 `progress: { lastSeq, excerpt, kind: 'waiting-input' }`；恢复后下一拍正常 excerpt（kind 缺省）
- worker 会话等待态 UI：看板卡「等你确认」（S6）消费 delegated 会话元数据 `byNode` 渲染「来自 {节点名}」

### 5.4 视图与导航

- `ViewKey` 加 `workgroups`；`SIDEBAR_VIEWS` 纳入（侧栏宽度/收起独立记忆）
- ViewSidebar 分发 `workgroups → WorkgroupSidebar`（组/成员列表）；MiddlePanel 分发 `workgroups → WorkgroupView`（监控台/查看模式二态）
- 既有组件迁移：GroupPanel 组管理逻辑拆入 WorkgroupSidebar/View；MirrorWizard 挂监控台组头；DelegationPanel 账本视图退役（被看板外派卡+监控台在跑行取代）；ViewPanel 重构为全宽 WorkgroupView 查看态；DelegationWizard 退役（UC9）
- HubSettingsPanel 瘦身保留：连接配置+consent+受控+迁移说明卡

## 6. 协议影响

**零改动**（协议维持 1.2.0 / v0.1.2）：

- `task.progress` 载荷为自由结构，加 `kind?` 字段向后兼容（hub 透传不校验）
- 任务书字段 `permissionTier` 经既有 payload 扩展承载（validate 未知容忍策略已有先例：modelBinding 可选段）
- waiting-input 摘要走既有 excerpt 通道（≤200 字符截断，不携敏感路径）

## 7. 安全

- 路由派发仍走既有 leader-only hub 校验（task.create 全链不变）
- L0 档位映射沙箱（seatbelt）+写授权系统，不新增权限面
- waiting-input/进度摘要不泄露：excerpt 截断红线沿用 M2 快照红线口径（禁携字段扫描不适用于此，但摘要仅任务书派生文本）
- 查看=只读不变：S4 全宽化不改 view.* 方法集，零写路径静态断言沿用

## 8. 测试策略

- **单测**：调度器选择矩阵（在线/离线/未镜像/平局/无候选）、路由守门（未镜像空间降级）、批量创建（N 行→N 任务+统一路由）、L1 超时（fake timers：等待超阈值→自动拒+steer 注入）、L1b 检测（sessionWaiting 翻转→kind 字段→恢复覆盖）、waiting 卡派生（leader/worker 双侧）
- **组件测**：WorkgroupView 二态（监控/查看）、看板混排卡六态、新建弹窗路由区（三选+降级+批量切换）、设置瘦身迁移卡
- **回归锁**：M2 六态迁移矩阵、consent 403 往返、只读零写断言、D6 续传、委派前置三拒——全部沿用不放宽
- **真机验收**（momo-acceptance）：双隔离实例全链——建组→镜像→看板建任务（组内调度）→自动派发→waiting-input（worker 等确认）→就地批准→完成回流；超时路径（不操作等 15min 缩短配置）→自动拒改道；worker 看板「来自」徽标；查看全宽四页签；设置瘦身无残留入口

## 10. 验收形态

双隔离实例真机：leader 看板建「组内调度」任务（含批量 4 条）→ 监控台见自动派发与在跑行 → worker 等确认时 leader 卡亮「等待节点确认」/worker 卡亮「等你确认」→ worker 就地批准 → 任务完成回流看板已完成列 → 全程设置页零协作入口；新实例 0 空间直接从工作组视图空态完成接入入组。
