# momo-hub M2.4 · 失败路径如实化与收尾硬化

- **状态**：待用户批准
- **日期**：2026-10-28
- **上游**：M2.3 终审 oracle 分诊（Important-1 + Minor×5）+ M2.3 真机验收 P3×2 + M2.2/M2.3 已知限制
- **定位**：无新功能面的收尾硬化批——把「失败路径说谎」清零，把测试/CI 护栏补齐，把分层倒置理顺。M3 能力（远程代答 / 多组 UI / 文件树）不在本期。

## 1. 背景与问题

M2.3 把版本取值链修对了，但**失败路径仍有一类共同缺陷：系统在拿不到真相时选择说好话**。

1. **「已是最新」可能是一句谎**（oracle Important-1）：`loadFresh()` 拉取失败时静默回落到 cache/lastGood 快照，且按设计**不写退避与 degraded**（P2-9 语义）。回落版本若恰好等于已装版本，`installHubPackage` 返回 `alreadyLatest: true`——用户看到「已是最新（v1）」，而同一张卡上「可更新」角标仍在，且这次失败对用户完全不可见。若 lastGood 缺失，回落 EMPTY_CATALOG 后条目找不到，用户看到「可能尚未接入 hub/已下架」——同样是假归因。
2. **worker 失败原因被泛化**（验收 D1）：`delegation-runner.ts:172` 取 `terminal.error ?? '未知错误'`，而 `TurnTerminal.error` 在上游映射中丢掉 provider 原始错误（如 401/模型不存在）。真机失败卡显示「执行失败:未知错误」，排查只能翻日志。
3. **leader 侧 reason 不对称**（oracle Minor-1）：`handleOnline` 重启终态补拍硬编码「中断前本地回合已失败」，不消费本分支新增的 `record.reason`。
4. **快照清单同 slug 冗余**（验收 D2）：`collectSkills` 对 `listInstalled()` 全量 push，marketplace 与 hub 记账同 slug 时 `config.skills` 出现重复条目（落装正确，清单不洁）。
5. **分层倒置**（oracle Minor/T5 concern）：`snapshot-builder` 为取记账集从 `mirror-applier` 导入，而 mirror-applier 本就依赖 snapshot-builder——传递依赖，抽取成本低。
6. **护栏缺失**：`main-forks` 项目置 `MOMO_RUNTIME_CHILD=1` 却未挂 IPC 守卫（`electron/vitest.config.ts:60-70`），污染风险只是「当前未触发」；e2e 未进 CI，选择器/等待漂移这类本次修过的缺陷会再回归。

## 2. 核心裁定

| 裁定 | 结论 |
|---|---|
| **R1 失败要如实，但不污染全局态** | 给 `HubCatalogLoad` 增 `stale: boolean`（本次加载是否命中回落快照），**不改** `degraded`/退避语义（P2-9 零刷屏不破）。安装链看到 `stale` 时如实报错或照常安装，不说「已是最新」 |
| **R2 人话优先于归因猜测** | `stale && 条目缺失` 报「无法获取 hub 最新目录」而非「可能已下架」——不替用户猜测服务端状态 |
| **R3 错误原文透传带脱敏与截断** | provider 错误 message 透传至 worker 卡（≤300 字符、`sk-****` 等密钥形态脱敏）；不新增字段、不改协议 |
| **R4 只补 skills 清单去重** | `config.resources` 早已有 type+slug 全局去重（`snapshot-builder.ts:477-484`，多成员引同一资源常态）；本次只给 `config.skills` 补同类 slug 去重，`resources` 条数与顺序不变 |
| **R5 hub 本期零代码改动** | 仅 CHANGELOG 追加 0.1.5 排序语义注记（文档）；不改协议、不改实现 |
| **R6 CI 覆盖只纳已稳定的 e2e** | macOS job 跑全量 e2e（15 pass/1 skip，约 2-3 min），失败上传 test-results；不引入 Linux xvfb 矩阵 |

## 3. 用户场景

| # | 场景 | 期望 |
|---|---|---|
| UC-P1-1 | hub 宕机 + 本地已装 v1 + lastGood 快照为 v1 → 点「更新」 | **失败通知**：「无法获取 hub 最新版本（请稍后重试）」；卡面角标保留；**绝不**出现「已是最新」 |
| UC-P1-2 | hub 宕机 + lastGood 缺失（首装后断网）→ 点「更新」 | 同上人话，**不**出现「条目可能已下架」 |

## 4. 契约与边界

### 4.1 `HubCatalogLoad.stale`（新增字段）

- `load()` 正常成功 → `stale: false`；`loadFresh()` 成功 → `stale: false`。
- `loadFresh()` 失败回落 cache/lastGood/EMPTY → `stale: true`（**不**写退避、**不**置 degraded）。
- `load()` 在退避窗口内命中 cache → 维持现状（stale 语义只服务安装链，浏览面继续用 `degraded`）。
- 消费方：仅 `installHubPackage`。`createHubProvider.list` 忽略该字段。

### 4.2 安装链失败语义

`installHubPackage(type, slug)`：

| 条件 | 行为 |
|---|---|
| `stale && !item` | throw `HubCatalogStaleError`（人话「无法连接到 momo-hub 获取最新目录（已装版本保持不变），请稍后重试」） |
| `stale && item && cmp(item.version, installed) <= 0` | throw `HubCatalogStaleError`（人话「无法确认最新版本（网络不可用），请稍后重试」）——**不得**返回 alreadyLatest |
| `stale && item && cmp > 0` | 照常安装（下载链是真闸门）；progress 链不变 |
| `!stale && !item` | 现状「未找到条目」文案保留 |
| `!stale && cmp <= 0` | 现状 alreadyLatest（UC-P1-3 不回退） |

`HubCatalogStaleError` 标记 `name='HubCatalogStaleError'` 供 IPC 层转人话（不暴露堆栈）。

### 4.3 provider 错误透传（T2 探查后定稿）

- 目标：`TurnTerminal.error` 在有原始错误时必为可读文本；`delegation-runner` 的 `?? '未知错误'` 只在真的无错误对象时兜底。
- 脱敏：`/[a-zA-Z0-9_-]{20,}/` 只对含 `key|token|authorization` 上下文的串处理；或复用既有脱敏工具（探查时确认是否已有）。
- 截断：≤300 字符，超出加 `…`。

### 4.4 其他

- `collectSkills` 去重：`Set<string>` 首见优先，顺序稳定（同源顺序 = 现状顺序）；`buildWorkspaceSnapshot` 的 resources 全局去重**保持原样**（既有实现）。
- `handleOnline`：`record.reason ?? '中断前本地回合已失败'`。
- `hub/accounting.ts` 新模块导出 `loadHubAccountingSet` + 缓存守卫 + 自愈；两消费方改导入路径，**零行为变更**。
- `alreadyLatest` 回执 `cachePath`：契约注记为「可能为空串（发布回填行）」；不做类型破坏。
- CI：**独立** `.github/workflows/e2e.yml`（`push`/`pull_request` → main；`build` → `electron-rebuild`（ABI 149）→ `pnpm e2e`；失败上传 `test-results/`）。`build.yml` 保持 tag 触发矩阵不动。

## 5. 非目标

- hub 代码改动（仅 CHANGELOG 一句）；协议字段；安装端点。
- 本地 stdio MCP 分发（域外，M3+）。
- readonly 标记持久化（进程内易失为既定设计，重启降级回约束段）。
- 镜像「已装旧版不升级」语义（既有镜像语义，记录边界）。
- marketplace 远程目录在 e2e 中的显式拦截（3s 超时 + bundled 兜底已足够）。
- M3 能力：远程代答 L2 / 多组 UI / 文件树 / headless runner / 无候选自动轮询。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| `stale` 误报（正常成功也置 true）→ 用户装不了 | 三态单测：fresh 成功/fresh 失败回落/fresh 失败无回落；且 stale 仅在失败分支置位 |
| 错误原文泄漏密钥进 UI/日志 | 脱敏单测（sk-/Bearer/token 形态）+ 截断长度断言 |
| CI e2e 不稳（Electron 在 runner 上） | 先本地全量复跑一次确认稳定；CI 首跑若 flaky，按 spec 降级为只跑 hub-distribution 六场景（记录于计划） |
| 分层抽取引发行为漂移 | 纯搬移：函数体零改动 + 既有 mirror-applier/snapshot-builder 单测全绿为验收 |
| `main-forks` 挂守卫后破坏既有用例 | 守卫语义与 agent-threads 完全相同（同文件复用）；全量 forks 两项目一次跑绿 |

## 7. 已知限制（本期不修，留存）

- M2.3 遗留：镜像对已装旧版不升级（记录边界）；hub 目录 items 排序取 semver-max 行 published_at（确定性变化）。
- M2.4 后仍存：provider 错误若在上游 SDK 内部即被吞（探查确认无救），则记录为外部依赖限制。
